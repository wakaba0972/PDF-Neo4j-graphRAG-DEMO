# 交接紀錄

## 專案現況

- Gradio 單機 PDF GraphRAG 工具，程式位於 `src/manual_graphrag/`。
- 每個專案代表一個車型；同車型多份 PDF 共用一張專案專屬 Neo4j database，支援 Schema 規劃、圖譜抽取、問答及自動評測。

## 頁面流程

- 頁面分流：登入畫面（登入後才顯示工具）、0 系統設定（共用 OpenAI API、中央題目集管理、專案題目集綁定）；1-0～1-5 是單一專案流程，2-0 是跨專案實驗（原 2-1 成員專案連線測試與 2-2 自動實驗測試都已併入 2-0），3-0～3-1 是人工抽樣／評測，4-0 是 AI／人工結果比較。
- PDF 摘要頁及自動 PDF routing 已移除。專案內問答直接查詢目前車型專屬 database 的所有文件證據。
- 專案 database 名稱由專案 ID 穩定雜湊產生；舊專案載入時會推導名稱。連線測試會以 `system` database 建立專案 database。
- 建立多資料庫需 Neo4j Enterprise 及管理權限；Community／Aura 不支援。刪除專案不會自動 drop Neo4j database，避免無法復原的資料刪除。
- 1-0 支援匯出／匯入 ZIP 專案封裝，內容是整個 `data/projects/<project-id>/` 本機資料夾（設定、PDF、題庫、建圖狀態、評測／實驗資料及 exports）。匯入會產生新專案 ID 與新 Neo4j database 名稱，並重設 PDF 路徑。
- 0 系統設定的「題目集管理」可匯入、預覽與刪除中央題目集；刪除前會提示綁定專案數。「專案綁定題目集」將中央題目集綁定到單一專案，1-4／1-5 與跨專案實驗均依此讀取題目集。
- 專案 `project.json` 保持精簡；`chunks.json.gz` 與 `graph.json.gz` 保存大型 chunks、實體與關係 sidecar，載入專案時可延後讀取圖譜明細；`pages.json.gz` 保存逐頁解析結果與人工檢查狀態。
- 封裝不含 `.env`、模型服務憑證或外部 Neo4j Database 本體；若有建圖狀態，匯入後會標記為尚未匯入 Neo4j，需重新 Embedding 並匯入。封裝含專案設定中的 Neo4j 明文密碼，ZIP 未加密，分享前需特別留意。

## 設定

- API endpoint、API key 與 Neo4j 憑證放在 `.env`，不寫入 `project.json`。
- `config/model_settings.yaml` 保存模型清單與用途選擇；API Key 僅設於「0 系統設定」。自動測試／實驗中的模型選擇保存在各自的專案設定中。
- Chat completions 不設定 `max_tokens`，實際限制由模型服務決定。
- 模型與 Embedding 服務統一使用 OpenAI-compatible API。連線測試只是診斷工具，不是工作流程的前置條件；實際 API 請求會驗證可用性並回報錯誤。
- 實驗專案回答模型已與單一專案共用 `MODEL_OPENAI_API_BASE`／`MODEL_OPENAI_API_KEY`；舊 `EXPERIMENT_MODEL_OPENAI_*` 變數會在下次保存 `.env` 時移除。
