# 檢索策略擴充指南

本專案目前提供五種檢索策略：基本向量檢索、混合檢索、Agentic Search、Agentic Search 2、Agentic Search 3。策略模組放在 `strategies/`，App 啟動時讀取 `specifications/*.yaml`；YAML 宣告穩定 ID、顯示名稱、實作入口和參數，UI、參數驗證、設定保存及執行分派都共用這份註冊資訊。新增策略不需要分別修改問答、評測和實驗頁。

## 實作介面

策略 class 必須提供：

- strategy_id：與註冊規格一致的穩定 ID。
- result_formatter：Neo4j retriever 使用的結果 formatter。
- retrieve(context, config)：執行檢索，回傳 list[dict[str, Any]] 證據。

context 是 RetrievalContext，提供 Neo4j driver/database、問題、embedding、
索引名稱、共用 Cypher 查詢、read retry，以及目前回答模型的 API 連線資訊。config 是已驗證的
RetrievalConfig；Top K 在 config.top_k，此策略獨有參數在 config.params。

證據 dictionary 應維持現有 evidence 結構，至少保留 `evidence_id`、`kind`、`text`、
`source_documents`、`source_pages`、`source_chunk_numbers`、`score`、
`fusion_score` 和 `matched_by`。共用流程會處理證據來源顯示、Reranker、圖譜證據擴展、Top K 和評測指標。

## YAML 規格

在 `strategies/specifications/<id>.yaml` 宣告策略 ID、顯示名稱、實作檔/class，及參數型別、預設值、上下界和 UI 控制：

    id: beam
    name: Beam 檢索
    implementation:
      file: beam/strategy.py
      class: BeamRetrievalStrategy
    parameters:
      beam_width:
        type: integer
        label: Beam 寬度
        default: 4
        minimum: 1
        maximum: 16
        control: slider

設定頁會依規格呈現原生 Gradio 控制項，並把策略 ID 與參數保存到 `retrieval_config`；執行前由 `RetrievalConfig` 驗證。

## 內建策略概覽

- **基本向量檢索 (`vector`)**：以問題向量查詢 Neo4j 向量索引，再透過 Cypher 回取來源證據。
- **混合檢索 (`hybrid`)**：使用 HybridCypherRetriever 結合向量與全文搜尋。
- **Agentic Search (`agentic`)**：先向量搜尋，再由程式從起始證據沿圖譜關係取得有限候選；LLM 選擇值得延伸的實體或停止。LLM 不撰寫 Cypher。
- **Agentic Search 2 (`agentic_search_2`)**：先向量搜尋作為起點，再由 LLM 多輪規劃唯讀 Cypher；程式驗證標籤與關係類型後執行並回傳結果，直到模型停止或輪數／時間上限到達。專案可將文件合併或按 `document_id` 分區；圖邊不跨文件分區。
- **Agentic Search 3 (`agentic_search_3`)**：先取向量起始證據，再交由 LLM 透過 OpenAI tool-calling 自主選擇固定工具：全文搜尋、沿實體關係擴展、取回來源 chunk。程式執行工具並將結果交回模型，模型可連續選工具或停止；它不能提交任意 Cypher。搜尋完成後，既有回答流程會使用取回證據產生最終答案。

### Agentic Search 參數

`agentic` 先用向量搜尋取得起點證據，沿 `MENTIONS_ENTITY` 找到起始實體；之後每一回合查詢真實的 `EXTRACTED_RELATION` 鄰居，將受限候選提供給目前選用的回答模型，讓模型選擇下一批實體或停止。模型只回傳候選 ID，不會產生或執行 Cypher。程式限制最大跳數、每輪分支數及候選數，再透過 `MENTIONS_ENTITY` 找回選中路徑連到的原文 chunk。

此策略的主要參數為 `seed_top_k`（起點證據數）、`max_hops`、`max_branches`、`hop_decay` 與起點 `effective_search_ratio`。預設最多兩跳；如果模型輸出無效選擇，會安全停止擴展，不會退回「展開所有鄰居」。策略會交錯排列起點與 Agent 選中的原文證據，避免未啟用 reranker 時新增證據被 Top K 截掉。

### Agentic Search 2 參數

`agentic_search_2` 的策略規格定義 `seed_top_k`（向量起點數）、`max_rounds`（LLM 搜尋輪數）、`result_limit`（每輪查詢上限）、`max_runtime_seconds`（總時間上限）及 `effective_search_ratio`。候選總量仍受共用 Top K／候選預算限制。模型產生的 Cypher 只允許受限的唯讀圖譜查詢，不可跨出目前建圖批次，也不可執行寫入、管理指令或任意程序呼叫。回傳結果會以 `evidence_id` 去重。

### Agentic Search 3 參數與安全範圍

主要參數為 `seed_top_k`、`max_tool_calls`、`result_limit`、`max_runtime_seconds` 與起點 `effective_search_ratio`。工具查詢由程式固定，不接受模型提供 Cypher；所有 Neo4j 查詢使用唯讀交易，限定在專案資料庫的圖譜標籤與應用程式允許的關係類型。圖譜擴展及來源 chunk 工具只接受 Agent 本輪已取得的證據 ID，避免模型任意指定圖譜節點。每次工具回傳都去重後交回模型，最終證據仍受 `candidate_top_k` 與共用 Top K 限制。

三種 Agentic 策略都屬於 Agentic reasoning，但流程不同：第一種由程式查詢鄰居、LLM 選路；第二種由 LLM 提議受限 Cypher、程式驗證並執行；第三種由 LLM 從固定工具中自行選擇與串接呼叫。模型的 `reasoning_effort` 是每次 LLM 呼叫的另一個設定，不等同策略輪數或工具呼叫數。

## 與共用流程的界線

策略模組負責如何查詢與整理候選證據。Top K、Reranker（字詞排序或 LLM Reranker）、證據擴展、來源記錄及 Evidence Hit Rate／Evidence Precision／Document Hit Rate 由共用流程處理。參數宣告於 YAML 後會自動出現在單題問答、自動問答及實驗組的原生 Gradio 元件中，並隨 `retrieval_config` 保存。若要新增的是所有策略共用的後處理能力，先改共用流程，再讓策略設定採用它；避免在各 UI callback 重複加入策略判斷。

## 文件圖譜範圍

1-3 的圖譜範圍預設為 `merged`，維持舊的單一圖譜語意；`per_document` 則逐份 PDF 抽取，並在同一個專案 database 建立多個 `GraphDocument`。文件模式以 SHA-256 `document_id` 作為分區鍵：`ExtractedEntity` 的身份包含文件 ID，關係端點只在相同 ID 內連接，`GraphEvidence` 也記錄文件 ID。跨文件即使有同名實體也會各自保留，不會自動建立跨文件關係。

兩種模式都使用專案共用的 Embedding 模型與同一個維度向量索引。現有策略仍對專案全部文件進行檢索，Agentic 圖遍歷沿著實際分區內關係前進；證據擴展則同時比對 `document_id` 和 chunk 編號。切換範圍後必須重新抽取並匯入，以免抽取時的實體合併狀態與 Neo4j 分區設定不一致。此資料邊界支援未來把單份文件派給獨立 Agent，但 Agent 派工、跨 Agent 證據融合與衝突處理尚未實作。
