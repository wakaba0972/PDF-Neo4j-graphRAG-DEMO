# 檢索策略擴充指南

本專案提供基本向量檢索、混合檢索、多種 Agentic Search 與 Greedy DFS Agentic Search。策略模組放在 `strategies/`，App 啟動時讀取 `specifications/*.yaml`；YAML 宣告穩定 ID、顯示名稱、實作入口和參數，UI、參數驗證、設定保存及執行分派都共用這份註冊資訊。新增策略不需要分別修改問答、評測和實驗頁。

## 實作介面

策略 class 必須提供：

- strategy_id：與註冊規格一致的穩定 ID。
- result_formatter：Neo4j retriever 使用的結果 formatter。
- retrieve(context, config)：執行檢索，回傳 list[dict[str, Any]] 證據。

context 是 RetrievalContext，提供 Neo4j driver/database、問題、embedding、
索引名稱、共用 Cypher 查詢、read retry，以及目前回答模型的 API 連線資訊。config 是已驗證的
RetrievalConfig；Top K 在 config.top_k，此策略獨有參數在 config.params。

證據 dictionary 應維持現有 evidence 結構，至少保留 `evidence_id`、`kind`、`text`、
`source_documents`、`source_pages`、`source_chunk_numbers`、`score`、
`fusion_score` 和 `matched_by`。共用流程會處理證據來源顯示、Reranker、圖譜證據擴展、Top K 和評測指標。

## YAML 規格

在 `strategies/specifications/<id>.yaml` 宣告策略 ID、顯示名稱、實作檔/class，及參數型別、預設值、上下界和 UI 控制：

    id: beam
    name: Beam 檢索
    implementation:
      file: beam/strategy.py
      class: BeamRetrievalStrategy
    parameters:
      beam_width:
        type: integer
        label: Beam 寬度
        default: 4
        minimum: 1
        maximum: 16
        control: slider

設定頁會依規格呈現原生 Gradio 控制項，並把策略 ID 與參數保存到 `retrieval_config`；執行前由 `RetrievalConfig` 驗證。

## 內建策略概覽

- **基本向量檢索 (`vector`)**：以問題向量查詢 Neo4j 向量索引，再透過 Cypher 回取來源證據。
- **混合檢索 (`hybrid`)**：使用 HybridCypherRetriever 結合向量與全文搜尋。
- **Agentic Search (`agentic`)**：先向量搜尋，再由程式從起始證據沿圖譜關係取得有限候選；LLM 選擇值得延伸的實體或停止。LLM 不撰寫 Cypher。
- **Agentic Search 3 (`agentic_search_3`)**：先取向量起始證據，再交由 LLM 透過 OpenAI tool-calling 自主選擇固定工具：全文搜尋、沿實體關係擴展、取回來源 chunk。程式執行工具並將結果交回模型，模型可連續選工具或停止；它不能提交任意 Cypher。搜尋完成後，既有回答流程會使用取回證據產生最終答案。
- **Agentic Search 4 (`agentic_search_4`)**：先取向量起始證據，再由 LLM 自主選擇固定唯讀工具。圖譜工具每次只擴展一跳，LLM 必須指定已找到的 evidence ID 作為起點，降低無關節點一路擴展的機會；關鍵字搜尋、圖譜擴展與取回原文 chunk 的結果都依 evidence ID 去重，存入大小受限的候選池。搜尋結束後另由 LLM 依問題相關性、答案涵蓋度與來源原文優先原則，挑選並排序最終 Top K。未被選作擴展起點的證據仍可被選入最終 Top K。它不使用共用 Reranker 或證據擴展後處理。
- **Greedy DFS Agentic Search (`greedy_dfs_agentic_search`)**：先以向量結果作為 DFS 起點。程式維護路徑堆疊、已擴展 evidence ID 集合及候選池；每一步僅查詢目前節點的一跳鄰接證據，再讓 LLM 判斷目前路徑是否足以回答，並排序值得繼續探索的候選。程式先深入排序最高的分支，把其餘候選留在堆疊中；分支走到底、達到深度上限或被判定不值得延伸時，就回溯探索下一個分支。答案路徑一旦被判定足夠便停止搜尋，最後由 LLM 從有界候選池選出 Top K。每次圖譜讀取均由程式固定唯讀 Cypher 實作，不接受模型生成的 Cypher；不使用共用 Reranker 或證據擴展後處理。
- **Greedy DFS Agentic Search 2 (`greedy_dfs_agentic_search_2`)**：保留 Greedy DFS 的探索和回溯方式，但將候選池改為分支專屬、動態維護。每一步讓 LLM 從目前路徑證據中挑出仍相關的項目，並排序要繼續探索的相鄰證據；被移除的證據不會進入該路徑的後續候選池。回溯到兄弟分支時，只帶入共同路徑上保留的項目，不會混入已放棄分支的專屬證據。找到足以回答的路徑後停止，最終只從該路徑候選池選 Top K；若搜尋預算耗盡仍未找到答案，使用最佳終止路徑。每次圖譜讀取均由程式固定唯讀查詢，不接受模型生成的 Cypher；不使用共用 Reranker 或證據擴展後處理。

### Agentic Search 參數

`agentic` 先用向量搜尋取得起點證據，沿 `MENTIONS_ENTITY` 找到起始實體；之後每一回合查詢真實的 `EXTRACTED_RELATION` 鄰居，將受限候選提供給目前選用的回答模型，讓模型選擇下一批實體或停止。模型只回傳候選 ID，不會產生或執行 Cypher。程式限制最大跳數、每輪分支數及候選數，再透過 `MENTIONS_ENTITY` 找回選中路徑連到的原文 chunk。

此策略的主要參數為 `seed_top_k`（起點證據數）、`max_hops`、`max_branches`、`hop_decay` 與起點 `effective_search_ratio`。預設最多兩跳；如果模型輸出無效選擇，會安全停止擴展，不會退回「展開所有鄰居」。策略會交錯排列起點與 Agent 選中的原文證據，避免未啟用 reranker 時新增證據被 Top K 截掉。

### Agentic Search 3 參數與安全範圍

主要參數為 `seed_top_k`、`max_tool_calls`、`result_limit`、`max_runtime_seconds` 與起點 `effective_search_ratio`。工具查詢由程式固定，不接受模型提供 Cypher；所有 Neo4j 查詢使用唯讀交易，限定在專案資料庫的圖譜標籤與應用程式允許的關係類型。圖譜擴展及來源 chunk 工具只接受 Agent 本輪已取得的證據 ID，避免模型任意指定圖譜節點。每次工具回傳都去重後交回模型，最終證據仍受 `candidate_top_k` 與共用 Top K 限制。

### Agentic Search 4 參數與證據選擇

主要參數為 `seed_top_k`、`candidate_pool_ratio`、`max_tool_calls`、`result_limit`、`max_runtime_seconds` 與起點 `effective_search_ratio`。候選池上限為 `min(Top K × candidate_pool_ratio, 100)`；Top K 是最後交給回答模型的證據數量，不再限制搜尋期間可探索多少候選。Agent 每輪只擴展它選中的既有證據 ID，圖譜工具一次走一跳；未選來擴展的候選仍保留給最後選證。搜尋完成後 Agent 會再從整個候選池挑選並排序最多 Top K 筆，優先考慮直接支持問題、互補涵蓋問題各部分且不重複的原文證據。若模型沒有回傳有效 ID，程式以起點分數優先作為安全備援。候選池上限、工具呼叫數與搜尋時間共同限制成本和圖譜擴張量。

Agentic Search 系列都屬於 Agentic reasoning，但流程不同：Agentic Search 由程式查詢鄰居、LLM 選路；Agentic Search 3 由 LLM 從固定工具中自行選擇與串接呼叫；Agentic Search 4 另外採用有界候選池和最後的 LLM 選證；Greedy DFS 則由程式維護路徑與回溯堆疊，LLM 負責評估目前路徑並排序下一個分支。模型的 `reasoning_effort` 是每次 LLM 呼叫的另一個設定，不等同工具呼叫數。

Greedy DFS 及 Greedy DFS 2 共用 `seed_top_k`、`candidate_pool_ratio`、`max_depth`、`branch_width`、`max_expansions`、`result_limit`、`max_runtime_seconds` 及起始 `effective_search_ratio` 等限制。兩者都用 LIFO 堆疊先深入最高優先分支，再回溯到其他分支。版本 1 最後從本次搜尋累積的候選中選證；版本 2 則只從目前成功路徑的動態候選池選證。若版本 2 沒有找到足以回答的路徑，會採用最佳終止路徑；選證呼叫失敗時只在該路徑內以起始向量分數排序作備援。

## 與共用流程的界線

策略模組負責如何查詢與整理候選證據。共用 Reranker（字詞排序或 LLM Reranker）與證據擴展目前僅供基本向量檢索及混合檢索使用；來源記錄及 Evidence Hit Rate／Evidence Recall／Evidence Precision／Evidence F1／Document Hit Rate 由共用流程處理。Evidence Recall 以每題命中的唯一 Gold 文件-頁面數除以該題 Gold 文件-頁面總數；Evidence F1 是每題 Precision 與 Recall 的調和平均，兩者都對有 Gold 頁碼的題目取算術平均。參數宣告於 YAML 後會自動出現在單題問答、自動問答及實驗組的原生 Gradio 元件中，並隨 `retrieval_config` 保存。若要新增的是所有策略共用的後處理能力，先改共用流程，再讓策略設定採用它；避免在各 UI callback 重複加入策略判斷。

## 圖譜範圍

每個專案內所有 PDF 一起抽取並匯入同一張知識圖譜。相同實體可跨文件共用節點與關係，以保留跨文件的圖譜連結；來源文件、頁碼和 chunk 資訊仍記錄在證據來源中，供引用和檢索評測使用。逐文件分區建圖已移除，檢索策略不再依圖譜範圍切換或過濾。

先前以「每份文件各自一張圖譜」匯入的舊圖譜不會被程式自動改寫。若要讓舊專案恢復跨文件節點合併與連結，請重新抽取並匯入該專案的全部文件；重新匯入會取代該專案目前由本工具管理的圖譜資料。
