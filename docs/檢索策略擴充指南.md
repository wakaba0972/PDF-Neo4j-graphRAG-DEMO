# 檢索策略擴充指南

新增檢索策略時，建立一個策略模組，實作共同介面，再到
src/manual_graphrag/retrieval_strategies/registry.py 的 STRATEGY_CATALOG
新增一筆註冊資料即可。UI 選項、參數驗證和實作載入都由這筆註冊資訊驅動；
不必在問答頁、評測頁或實驗頁各加一次策略分支。

## 實作介面

策略 class 必須提供：

- strategy_id：與註冊規格一致的穩定 ID。
- result_formatter：Neo4j retriever 使用的結果 formatter。
- retrieve(context, config)：執行檢索，回傳 list[dict[str, Any]] 證據。

context 是 RetrievalContext，提供 Neo4j driver/database、問題、embedding、
索引名稱、共用 Cypher 查詢和 read retry。config 是已驗證的
RetrievalConfig；Top K 在 config.top_k，此策略獨有參數在 config.params。

證據 dictionary 應維持現有 evidence 結構，至少保留 score、
fusion_score、matched_by 和來源欄位，讓共用的擴展、重排、來源顯示及
Recall/MRR 流程能繼續使用。

## 註冊範例

在 catalog 加入一個三欄項目：顯示與驗證規格、Python module 路徑、策略 class 名稱。
參數規格使用 RetrievalParameterSpec 宣告型別、預設值、上下界和允許選項：

    (
        RetrievalStrategySpec(
            "beam", "Beam 檢索", {
                "beam_width": RetrievalParameterSpec(
                    int, default=4, minimum=1, maximum=16,
                ),
            },
        ),
        "manual_graphrag.retrieval_strategies.beam",
        "BeamRetrievalStrategy",
    ),

實驗組與單專案設定中的策略專屬參數 JSON 會呈現並保存該策略參數；
例如 {"beam_width": 8}。執行時，registry 依 module/class 路徑載入策略，
而 RetrievalConfig 會先依規格驗證參數。

## 與共用流程的界線

策略模組負責如何查詢與整理候選證據。Top K、圖譜證據擴展、Reranker、
來源記錄和評測統計由共用流程處理。新增策略不應直接改 UI callback；
若策略需要全新的共用流程能力，才另外擴充 RetrievalContext 或共用後處理。
