## 2. 目標與原則

### 目標

1. 提升正確證據被檢索到的機率。
2. 降低不相關或重複證據對回答的干擾。
3. 支援跨頁、實體關係及多輪追問問題。
4. 控制送入 LLM 的證據量、token 成本與回應時間。
5. 以可重複執行的評測數據驗證每項改善。
6. 保留答案來源頁碼，證據不足時明確拒答。

### 實施原則

- 先改善檢索精準度與可衡量性，再增加多跳遍歷等複雜功能。
- 所有檢索結果都必須能回溯至原文 chunk 與 PDF 頁碼。
- 新增行為時同步補充單元測試及整合測試。
- 每個階段完成後，以同一套評測集比較品質、速度與 token 使用量。
- 基本向量檢索保留為基準模式，方便與其他策略 A/B 比較。

## 3. PDF 多模態解析

來源：`feature/multimodal-diagram-parsing`（`f1dfc44`、`027c4e4`），2026-10-17 測試；A1～A5、A7、A8 與暫停／停止已於 `fix/multimodal-parsing-followups` 完成；A6、A10、A11 於 2026-10-19 完成。

**目前流程**：① 解析：偵測頁面圖表（A6），含圖表或無文字層的頁面將正文區（裁掉上下各 8%）渲染為 PNG → Vision 模型依視覺順序輸出 `text`（原文抄寫）、`table`（Markdown 表格）、`diagram`（圖表文字描述）→ 逐頁結果存入專案 `pages.json.gz`；② 逐頁人工檢查、修改；③ 依已保存的頁面內容切 chunk（不再呼叫 Vision）→ 抽取圖譜。圖片本身與圖表在頁面上的位置都**不保存**，檢索與問答只看得到文字描述；需要看原圖時由 A8 從專案內 PDF 即時偵測並裁切。Vision 失敗頁改用 PDF 文字層；掃描檔（無文字層）也能經 Vision 辨識。

**測試結果**：單元測試全部通過（423 passed；A7、A8 完成後 451 passed；A6、A10、A11 完成後 484 passed）。以 `EPSON_L485.pdf` 實測第 1、10、20 頁皆解析成功；圖表頁（第 20 頁）多出原本純文字擷取沒有的圖表描述，功能方向正確。

**A10 逐頁檢查**（2026-10-19）

- 1-1 以子頁籤分為「① 解析 PDF」「② 逐頁檢查」「③ 切分 chunk」三步，解析狀態訊息固定顯示在子頁籤上方；解析成功後自動切到「② 逐頁檢查」。「解析並加入專案」只產生逐頁結果，不再切 chunk；文件的 Chunk 數在切分前為 0。
- 逐頁結果存於 `data/projects/<id>/pages.json.gz`（`project_store.load_document_pages()`／`save_document_pages()`），格式 `{"documents": {檔名: {"pages": [...], "chunked": bool}}}`。每頁記錄 `page`、`text`、`source`（vision／text／fallback）、`reviewed`、`has_figures`（有用 Vision 時才偵測）、`fallback_reason`；人工修改後另存 `original_text` 供還原。移除文件時一併刪除；專案封裝自動包含。
- 檢查畫面：左邊 PDF 原頁影像、右邊可編輯的解析文字；可依「未檢查／Vision／文字層／Vision 失敗／含圖表／已修改」篩選，上一頁／下一頁只在篩選結果內移動，頁面總覽表點選可跳頁。按鈕：「儲存並標記已檢查（下一頁）」「還原原始解析」「以 Vision 重新解析此頁」（`pdf_service.analyze_pdf_page()`）「改用 PDF 文字層」。
- 頁面內容變動後 `chunked` 變為 false，檢查區顯示需重新切分。「依目前頁面內容切分 chunk」重新切分所有文件並重新編號；較早版本解析、沒有逐頁結果的文件沿用原 chunks（需重新解析才能逐頁檢查）。

**A6 解析範圍**（2026-10-19）

- `pdf_service.page_has_figures(page, kinds)`（與 `detect_page_figures()` 同一套規則，先查圖片／向量圖，最後才跑最慢的 `find_tables()`）；偵測失敗視為含圖表。
- 1-1「Vision 解析範圍」存於專案設定 `pdf_vision_scope`：
  - `figures`「僅含圖表或表格的頁面」（預設）
  - `tables`「只讀表格」：只送偵測到表格的頁面
  - `diagrams`「只讀圖表」：只送含圖片或向量圖的頁面
  - `all`「全部頁面」
- 無文字層的頁面（掃描）不論範圍一律送 Vision。送 Vision 的頁面仍**整頁**轉錄（Vision 結果取代整頁文字），範圍只決定哪些頁送出。
- `figure_pages`（逐頁檢查「含圖表」篩選、`has_figures`）不論範圍都記錄有任何元素的頁面；`text_layer_pages` 記錄因範圍而用文字層的頁面，解析訊息依範圍顯示「N 頁無表格／無圖片或向量圖／無圖表，直接使用文字層」。
- 表格誤判：`find_tables()` 會把插圖的標註引線當成表格格線（Samsung S25 第 66 頁 4×3 只有 1 格有字、第 109 頁工具列標籤 1×6；EPSON 第 54 頁），導致「只讀表格」送出插圖頁。改為表格的上緣與下緣都要有涵蓋 ≥ 90% 寬度的水平框線（線段或矩形邊）才算（`_has_table_border`），套用於所有偵測（含 A8 裁切）。實測：Samsung 表格頁 6 → 4 頁（32、38、203、204），EPSON 只少誤判的第 54 頁，單列表格（如「掃描器類型｜平台式」）保留。
- 已知限制：表格偵測範圍若把上方說明文字包進去（EPSON 第 134 頁圖文混合規格表），上緣沒有框線會被濾掉；該頁有其他表格所以不受影響，但類似頁面若只有這種表格會被當成無表格。無框線表格仍偵測不到。
- `EPSON_L485.pdf`（`figures` 範圍）：92 / 151 頁送 Vision、59 頁用文字層，偵測 7.2 秒（原完整偵測 10.4 秒），抽看 8 頁純文字頁未漏圖。漏判的頁面可在逐頁檢查用「以 Vision 重新解析此頁」補救。

**A8 偵測實測**（2026-10-17，`EPSON_L485.pdf` 151 頁）

- 151 頁中 92 頁偵測到圖表：表格 48、內嵌圖片 55、向量圖 94。全份偵測約 22 秒（`find_tables()` 每頁約 0.15 秒），即時裁切單一 chunk（1～5 頁）約 0.3 秒。
- PyMuPDF 原生 `cluster_drawings()` 會把一張插圖切成多塊（如第 20 頁裝置連線圖），也會把注意事項外框與插圖合併（第 40 頁）。改為自行分群：先排除長的水平／垂直框線與矩形（外框、分隔線、表格框線），其餘路徑相距 12 pt 內合併；忽略中心在頁首／頁尾、或圖片／向量圖短邊小於 36 pt 的元素；落在較大元素內超過一半面積者視為重複（表格內的小圖、插圖內被誤判的表格）。
- 已知限制：上下相鄰很近的兩張插圖偶爾會合併成一張（第 54 頁）；以路徑繪製的文字（如封面「L485 Series」）若夠大會被當成向量圖。表格偵測依賴框線，無框線表格可能偵測不到。

## 4. 各項目細節

### P0：評測集與指標 🟡

**已完成**

- 從 PDF 自動生題（含來源頁碼與 chunk），題目集可匯入、編輯、匯出，並集中管理與綁定專案。
- 單一專案與跨專案實驗：多實驗組、回答模型、檢索策略並行比較，AI 判分。
- 人工評測：3-0 分層抽樣與分派、3-1 盲評、4-0 AI／人工結果比較。
- 檢索指標：Evidence Hit Rate、Evidence Recall、Evidence Precision、Evidence F1、Document Hit Rate。

**待完成**

- 從實際 PDF 人工整理 30～50 題固定基準集，每題記錄問題、答案要點、正確來源頁碼／chunk、題型、是否有答案。
- 題型至少涵蓋：單段落、錯誤碼／型號／數值精確查詢、跨頁整合、實體關係／原因影響、無答案問題、多輪追問。
- 補充指標：無答案正確拒答率、平均與 P95 回應時間、每次問答的 context token 數。

### P1：全文與向量混合檢索 ✅

已完成 CJK 全文索引、官方 HybridCypherRetriever 與內建 naive ranker、run ID 隔離，以及 UI 顯示官方混合分數。後續只需以 P0 基準集確認精確詞查詢的 `Recall@K` 不低於基本向量檢索。

### P2：候選去重與重新排序 🟡

**已完成**：共用流程支援停用／詞彙 Reranker／LLM Reranker。

**待完成**

- 向量、全文、圖譜擴展結果先組成候選集合，依 `evidence_id`、來源 chunk 與文字相似度去重。
- 為所有候選計算統一分數，擴展證據不再固定為 `0.0`。
- 檢索來源介面顯示向量、全文、圖譜及最終分數。

建議初始公式（權重需以評測集調整）：

```text
final_score = 0.45 × vector_score + 0.25 × keyword_score
            + 0.20 × graph_score  + 0.10 × source_proximity_score
```

圖譜分數：直接命中實體 > 一跳關係＝關係來源原文 > 同 chunk 擴展 > 兩跳關係；無法回溯原文者不送入回答模型。

**驗收**：擴展證據有可解釋分數、依統一分數排序、重複證據比例下降且答案品質不退步。

### P3：Context token 預算 ⬜

- 新增 `max_context_tokens`，依回答模型 context window 預留 system prompt、問題與歷史、回答輸出空間。
- 依最終排序逐筆加入證據，超過預算即停止；限制單一 chunk 長度，合併相鄰重疊 chunk。
- 原文、實體、關係各設最低與最高比例，避免單一類型占滿。

**驗收**：不會因 Top K 或圖譜擴展超過 context window；問答紀錄包含實際證據數與估算 token 數。

### P4：有方向的圖譜擴展 🟡

**已完成**：Agentic Search（程式查鄰居、LLM 選路，限制跳數與分支）與 Agentic Search 3（LLM 以固定工具搜尋，不接受任意 Cypher）。詳見 [檢索策略擴充指南](檢索策略擴充指南.md)。

**待完成**

- 共用流程的圖譜擴展改為從高分實體出發：命中實體 → 一跳關係 → 鄰接實體 → 關係來源原文 → 統一 rerank → 依 token 預算組裝。
- 依問題類型限制可擴展的關係；預設一跳，比較／原因／影響／路徑題才考慮兩跳。
- 高度數節點降權，限制每個起點的最大關係數與總擴展數。

**驗收**：擴展結果能說明起點、關係與距離；關係型題目正確率高於基本向量檢索；一般事實題不退步。

### P5：多輪問答與問題改寫 ⬜

- 保存最近 3～5 輪問題與回答摘要，納入 token 預算。
- 檢索前將含代名詞或省略的追問改寫為獨立問題，同時保存原始與改寫後問題。
- 新對話或切換文件時清除歷史；使用者可手動清除。

```text
上一題：E01 應該如何處理？
追問：那如果還是沒有恢復呢？
改寫後：依照 E01 的排除步驟處理後，設備仍未恢復時，下一步應如何處理？
```

**驗收**：多輪評測題能正確解析指代；改寫不加入不存在的前提。

### P6：證據充分性判斷與二次檢索 🟡

**已完成**：Agentic 策略在搜尋迴圈中自行決定繼續或停止；回答 prompt 要求證據不足時明確說明。

**待完成**

- 共用流程在第一輪後判斷證據是否充分；不足時抽取關鍵實體、產生同義詞、拆解子問題或改用其他檢索方式。
- 合併兩輪候選後重新去重、排序並套用 token 預算；設定最多輪數。

**驗收**：每次二次檢索有可記錄的觸發原因；無答案題的臆測比例下降；延遲與呼叫次數在上限內。

### P7：依問題類型選擇檢索策略 ⬜

| 問題類型 | 建議策略 |
| --- | --- |
| 錯誤碼、型號、數值 | 混合檢索 |
| 實體定義或說明 | Local GraphRAG |
| 原因、影響、相互關係 | Agentic Search（實體起點＋關係遍歷） |
| 整份文件主題或趨勢 | Community summary／Global Search（見 [Microsoft GraphRAG 與 Neo4j 整合](Microsoft-GraphRAG與Neo4j整合.md)） |
| 多輪追問 | 問題改寫後再檢索 |

- 新增輕量分類器或規則判斷，自動選擇結果顯示於問答紀錄；保留手動指定模式。

**驗收**：分類準確率達門檻；自動模式整體品質高於固定單一策略。

## 6. 測試計畫

- **單元測試**：去重、統一評分、token 預算裁切、問題改寫、二次檢索觸發條件。
- **Neo4j 整合測試**：全文索引、run ID 隔離、一跳關係與來源 chunk 回溯、高度數節點與擴展上限、空資料庫與查詢錯誤處理。
- **UI 測試**：參數傳遞、分項分數顯示、多輪歷史保存與清除、錯誤訊息不清除既有有效狀態。
- **回歸評測**：每階段完成後執行固定評測集，與基本向量檢索及前一版比較；核心指標下降時先找出退步題型。

## 8. 風險與控制

| 風險 | 控制方式 |
| --- | --- |
| Vision 解析耗時與成本過高 | 並行處理、只對含圖表頁使用 Vision、顯示失敗統計 |
| 圖譜擴展帶入大量雜訊 | 限制跳數與每節點關係數，統一 rerank |
| 全文與向量結果重複 | 以 evidence ID、chunk 與文字相似度去重 |
| context 超限 | 強制 token 預算並預留回答空間 |
| 問題改寫產生錯誤前提 | 保存原始問題、限制改寫用途並加入測試 |
| 二次檢索增加延遲與成本 | 觸發門檻、最大輪數與逾時 |
| 建圖抽取品質限制檢索上限 | 追蹤實體／關係抽取準確率，保留原文兜底 |
| 指標改善但體感下降 | 同時檢查離線評測、人工評測與回應時間 |

## 9. 成功條件

- 正確來源的 Evidence Recall／Hit Rate 相較基準提升。
- 關係型與跨頁問題的答案正確率提升，引用頁碼正確可追溯。
- 無答案問題不會因圖譜擴展而增加臆測。
- 問答 context 不超過 token 預算，延遲與成本在可接受範圍內。
- 多輪追問不需使用者反覆補充主詞。
- 各檢索策略能以相同評測集持續比較。
